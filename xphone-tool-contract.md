# XPhone Agent tool contract

This file applies to XPhone Agent mode. The copied CradleOS `hooks/`, `repair/`, `tools/`, daily, Email, Holdings, and Maps prompt files are source references, not tools exposed in this run. The active role prompts are `os/osagent.md`, `os/osagent-direct-writer.md`, `subagents/messages.md`, and `subagents/socialmedia.md`, plus their included fragments. Follow only tools actually exposed in the current role session.

The trusted Agent gateway owns the content key and keeps OS and each character/app subagent in separate sessions. The Worker authenticates, queues, and forwards encrypted envelopes; it cannot read RP content. Never send message text, story state, or the content key as plaintext MCP arguments.

| Role-session tool | Worker MCP call made by the trusted gateway |
| --- | --- |
| `read_story_reference` | `story.get_context` lists authorized reference IDs; `story.read_reference` reads one authorized document for the current `consumer`. |
| `observe_surface` | `xphone.request_observation` sends an encrypted, targeted request; `xphone.read_inbox` receives the client's encrypted result. Use it for actual Messages or social history, state, and event logs only when needed. |
| `submit_app_actions` | `xphone.submit_action_batch` sends an encrypted action batch; `xphone.get_delivery` and the encrypted client receipt establish whether it was applied. |
| `delegate_character_message`, `delegate_social_action`, `report_to_os` | Local session routing in the trusted gateway. They are **not** MCP tool names. The gateway starts the assigned role session and retains only its permitted context. |

Before an action, call `xphone.list_app_actions` for the live AppAction schema. This run supports `agent.reply` in the fixed OS Messages conversation; `messages.append` in the assigned character DM; `socialmedia.applyBatch` for Instagram, X, and Reddit posts/comments; `notes.create`, `notes.update`, `world.applyStatePatch`; and `journal.appendMainRecord`. Instagram, X, and Reddit share the socialmedia action type. There are no Email, group Messages, Maps-write, or structured-message AppActions in this run.

For incoming client events, the gateway uses `xphone.open_event_stream` or `xphone.read_inbox`, decrypts the event, selects its OS/subagent route, calls `xphone.start_event`, renews a long turn with `xphone.renew_event`, then calls `xphone.finish_event` and `xphone.ack_inbox`. MCP cannot wake an Agent process that is offline; the gateway must stay connected or be started by an Agent platform's inbound API.

For a G5 Dashboard main record, stream encrypted `start` and `update` frames through `xphone.submit_journal_stream_frame` while text is generated. Then submit the exact finished Markdown as `journal.appendMainRecord` with the same `tickId`, wait for the client receipt, and only then delegate later character/social actions. `xphone.schedule_delivery`, `xphone.cancel_schedule`, and `xphone.list_schedule` schedule encrypted delivery only; they do not run a model or monitor real-world news.

On the first `app.foreground` of a new Agent save, the trusted gateway reads `story/config/initialContent.json` with `runtime.read_asset` before running the OS model. Its `journal.markdown` is an authored opening: send it unchanged through encrypted Journal frames and one `journal.appendMainRecord` action. Its `messages` entries are authored first messages: resolve each `actorName` to the current client's actor/thread directory and submit encrypted `messages.append` actions before any model-authored character message. Do not ask a model to invent or paraphrase this opening or these first messages. Use stable action IDs and skip each batch once applied so a resumed delivery does not add duplicates.

Load prompt/config files with `runtime.list_assets` and `runtime.read_asset`. These transport tools expose copied source files from private R2, including raw truth configuration, to the authenticated Agent endpoint. A trusted gateway may read `story/config/narrativeTruth.json` to calculate the role's truth projection, but must never pass that raw file to the OS or subagent model session. The current MCP token does not separate gateway-only files from model-readable files; direct raw MCP access by an untrusted hosted Agent is not approved for truth-isolated play. Use `story.get_context` and `story.read_reference` for consumer-scoped story documents.

## Image generation and encrypted attachment contract (`imageUrl` & `imageNonce`)

All image actions use the standardized field `imageUrl` (string) and optional `imageNonce` (string, base64).
Images generated by Muse/Agent MUST be encrypted end-to-end to protect transmission privacy:

1. **Generation & Encryption Pipeline**:
   - Generate the image on the agent/Muse side using native image generation.
   - Encrypt the raw image bytes using the current session's `content key` via AES-256-GCM (12-byte random nonce, empty AAD).
   - Post the encrypted ciphertext to the Worker blob endpoint:
     `POST /agent/blob` (Header: `Authorization: Bearer <agentToken>`)
     Body: `{ "data": "<base64_ciphertext>", "mimeType": "image/webp" }`
     Response: `{ "blobId": "<uuid>" }`
   - In the action payload, pass `imageUrl: "blob:<blobId>"` and `imageNonce: "<base64_nonce>"`.

2. **Actions supporting encrypted images**:
   - `agent.reply`: `{ messageId: string, text: string, imageUrl?: "blob:<blobId>", imageNonce?: string, messageType?: "image" | "text" }`
   - `messages.append`: `{ threadId: string, from: string, text: string, imageUrl?: "blob:<blobId>", imageNonce?: string, messageType?: "image" | "text" }`
   - `socialmedia.applyBatch`:
     - `appendPost`: `{ platform: "x" | "reddit" | "instagram", operation: "appendPost", author: string, title?: string, content: string, imageUrl?: "blob:<blobId>", imageNonce?: string }`
     - `appendComment`: `{ platform: "x" | "reddit" | "instagram", operation: "appendComment", target: string, author: string, content: string, imageUrl?: "blob:<blobId>", imageNonce?: string, replyTo?: string }`

3. **Client Decryption**:
   The XPhone client detects the `blob:` prefix, retrieves the encrypted blob from Worker, and decrypts the image locally using the content key + `imageNonce` before rendering. Legacy http(s) URLs remain supported for backwards compatibility.
